# Actor 可测性约束

**编写测试脚本时必须同时使用 `ue-autotesttools-core`。** 只有在实际编写或维护测试时，才按需读取 [Actor 测试接口参考](../../references/actor-testing-api.md)；设计业务实现时不要加载接口细节。

## 约束

- 使用类、接口、标签、组件、所有者、发起者、网络角色或精确对象组成稳定选择条件；临时对象名和编辑器标签只能用于兼容场景。
- 多对象结果必须具有确定顺序；条件不足以唯一定位时，显式处理多个结果，不任取一个对象。
- 用显式 fixture 建立类、变换、关系和延迟构造阶段；不要依赖关卡中的偶然对象或上一用例残留。
- 属性变更必须可逆。安全值记录原值并恢复；存在外部副作用的变更必须先登记幂等、可重试的显式清理。
- 把生成、组件变化、结束播放和销毁作为可观察事件；等待条件成立，不用固定延时推断生命周期。
- 明确 World、PIE 会话和资源所有权。最终清理时先关闭观察流，再恢复属性和销毁 fixture；若测试本身需要观察结束或销毁，则在观察流开启时显式触发并消费事件。失败后仍须可重试清理。

## 可测类别

- Actor 的稳定查询、等待和确定性枚举。
- 即时或延迟生成、所有者与发起者关系、组件存在性。
- 反射属性读取、可逆修改和显式副作用清理。
- 生成、组件变化、结束播放与销毁的生命周期事件及顺序。

## 反模式

- 把自动生成名称、编辑器标签、模糊匹配或枚举首项当作业务身份。
- 用固定等待、截图或对象是否消失代替逻辑事件。
- 自动恢复对象引用、容器、委托或带 setter 的属性。
- 手工销毁测试对象，却绕过尚未完成的观察、恢复或显式清理。
